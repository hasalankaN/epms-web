# Backend Issues & Missing Values Tracker

This document tracks bugs, missing fields, and inconsistencies found in the backend APIs during frontend integration.

| Date | Endpoint | Issue / Missing Values | Status |
| :--- | :--- | :--- | :--- |
| 2026-04-08 | `GET /api/v1/admin/certificate-requests` | **Missing Field**: `verification_no` is required by the design but missing from the API response. | Resolved — each item now includes `verification_no` (subquery from `issued_certificates`) and `null` if not yet issued. |
| 2026-04-08 | `GET /api/v1/admin/certificate-requests` | **Missing Field**: `issued_at` date is missing. Currently falling back to `created_at`. | Resolved — each item now includes `issued_at` from `issued_certificates` (null if not yet issued). |
| 2026-04-08 | `GET /api/v1/admin/certificate-requests` | **Data Inconsistency**: API provides `IN_PROGRESS` but the design requires "Printing in progress". | Resolved (Frontend mapping) — API now also returns `effective_status` field. Frontend should map `IN_PROGRESS` → "Printing in progress". |
| 2026-04-08 | `GET /api/v1/admin/certificate-requests` | **Missing Status**: "Issued" status is shown in the design but not listed in the API's available values. | Resolved — API now returns `effective_status: 'ISSUED'` when a matching `issued_certificates` record exists; otherwise mirrors raw `status`. |
| 2026-04-08 | `PATCH /api/v1/admin/certificate-requests/:id/status` | **Missing Endpoint**: Required to update certificate status (e.g., "Mark as Delivered"). Mocked on frontend. | Resolved — endpoint added. Accepts `{ status: 'PENDING' \| 'IN_PROGRESS' \| 'DELIVERED' \| 'DOWNLOADED' }`. |
| 2026-04-08 | `DELETE /api/v1/admin/certificate-requests/bulk` | **Missing Endpoint**: Required for bulk deleting certificate requests. Mocked on frontend. | Resolved — endpoint added. Accepts `{ ids: string[] }` in the request body. |

Full `triggered_by_user_id` enrichment is deferred. |
| 2026-04-16 | `GET /api/v1/admin/students/{id}` | **Missing Feedback**: `certificate_status` for individual courses/batches was expected but sometimes returns null or inconsistent values compared to the "Certificate Requests" module. | Resolved — `certificate_status` returns `'Issued'` or `'Pending'` per enrolled course/batch row. |
| 2026-04-16 | `GET /api/v1/admin/enrollments/{id}/payment-details` | **Requirement**: Dedicated endpoint for fetching grouped payment/installment data for a specific enrollment.
