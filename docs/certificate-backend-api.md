## Domain Overview

The certificate system has two main concepts:

| Concept | Description |
|---------|-------------|
| **Certificate Template** | The design — a background image + configured text tag positions |
| **Issued Certificate** | A real certificate generated by merging a template with a specific student + course data |

**Flow:**
```
Admin creates Template → Admin configures Tag positions → Student completes course
→ System issues Certificate → Renders PDF with dynamic field values overlaid on template
```

### `signature_layout` JSON Column Structure (stored in `certificate_templates.signature_layout`)

This is an **optional** JSON object stored when the admin adds a digital signature to the template. If the admin does not enable a signature, this column is `NULL`.

```json
{
  "x": 70.0,
  "y": 85.0,
  "width": 15,
  "opacity": 100,
  "rotation": 0
}
```

| Field | Type | Description |
|-------|------|-------------|
| `x` | `float` (0–100) | Horizontal center position as percentage of template image width |
| `y` | `float` (0–100) | Vertical center position as percentage of template image height |
| `width` | `integer` (5–50) | Signature width as percentage of template image width |
| `opacity` | `integer` (10–100) | Opacity percentage |
| `rotation` | `integer` (-180–180) | Rotation in degrees |

> **Note:** The `enabled` flag from the frontend `SignatureState` is **not stored** in the database. If a signature file is uploaded and a `signature_layout` exists, the signature is considered enabled. If no signature file is present, it is disabled.

## Tag System Explained

Each tag in `tag_layout` has:

| Field | Type | Description |
|-------|------|-------------|
| `x` | `float` (0–100) | Horizontal position as **percentage of template image width** |
| `y` | `float` (0–100) | Vertical position as **percentage of template image height** |
| `properties.fontSize` | `integer` (px) | Font size in pixels |
| `properties.fontColor` | `string` (hex) | Text color e.g. `"#E60076"` |
| `properties.fontFamily` | `string` | Full CSS font-family string |
| `properties.fontWeight` | `enum` | `"normal"`, `"medium"`, `"semibold"`, `"bold"` |
| `properties.opacity` | `integer` (0–100) | Opacity percentage |

**How to render a tag onto the image:**

```
pixel_x = (tag.x / 100) * image_width_px
pixel_y = (tag.y / 100) * image_height_px

font_weight_map = {
  "normal":   400,
  "medium":   500,
  "semibold": 600,
  "bold":     700
}

alpha = tag.properties.opacity / 100   # 0.0 – 1.0
```

### 4. Issued Certificates

---

#### `POST /api/certificates/issue`

Issue a certificate to a student.

**Content-Type:** `application/json`

**Request Body:**
```json
{
  "templateId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "studentId": "student-uuid-here",
  "courseId": "course-uuid-here",
  "batchId": "batch-uuid-here"
}
```

**Backend Actions:**
1. Look up template → get `tagLayout` + `signatureLayout` + `templateFileUrl` + `signatureFileUrl`
2. Look up student → get `full_name`
3. Look up course → get `name`
4. Generate `verification_no` (e.g. `CERT-2026-00042`)
5. Set `issued_date` to today
6. Render the certificate PDF, including signature if present (see [Certificate Generation Logic](#certificate-generation-logic))
7. Upload PDF to storage
8. Save `issued_certificates` record
9. Increment `template.issued_number` by 1

**Response `201 Created`:**
```json
{
  "id": "issued-cert-uuid",
  "templateId": "3fa85f64-...",
  "studentId": "student-uuid",
  "courseId": "course-uuid",
  "batchId": "batch-uuid",
  "verificationNo": "CERT-2026-00042",
  "status": "Issued",
  "issuedDate": "2026-03-05",
  "generatedPdfUrl": "https://storage.example.com/certificates/issued/CERT-2026-00042.pdf"
}
```

## Full Payload Reference

### `TagProperties` Object

```json
{
  "fontSize": 14,
  "fontColor": "#000000",
  "fontFamily": "Inter",
  "fontWeight": "semibold",
  "opacity": 100
}
```

| Field | Type | Constraints |
|-------|------|-------------|
| `fontSize` | `integer` | min: `6`, max: `120` (pixels) |
| `fontColor` | `string` | Valid hex color: `#RRGGBB` |
| `fontFamily` | `string` | Any string (CSS font-family value) |
| `fontWeight` | `string` | Must be: `"normal"`, `"medium"`, `"semibold"`, or `"bold"` |
| `opacity` | `integer` | `0` – `100` |

---

### `TagState` Object (per tag in `tagLayout`)

```json
{
  "x": 50.0,
  "y": 30.0,
  "properties": {
    "fontSize": 14,
    "fontColor": "#000000",
    "fontFamily": "Inter",
    "fontWeight": "semibold",
    "opacity": 100
  }
}
```

| Field | Type | Constraints |
|-------|------|-------------|
| `x` | `float` | `0.0` – `100.0` (% of image width) |
| `y` | `float` | `0.0` – `100.0` (% of image height) |
| `properties` | `object` | See `TagProperties` above |

> `sampleValue` is **not** sent in any API payload — it is a frontend-only preview value.

```json
{
  "x": 70.0,

  "opacity": 100,
  "rotation": 0

```

| Field | Type | Constraints |
|-------|------|-------------|

## Certificate Generation Logic

When `POST /api/certificates/issue` is called, the backend must render the certificate PDF by overlaying each tag's dynamic value onto the template image at the configured position.

### Steps

```
1. Load templateFileUrl → decode image to bitmap (PNG/JPEG)
2. Get image dimensions: width_px, height_px
3. For each tag in tagLayout:

   a. Resolve dynamic value:
      - certificateId  → issued_certificates.verification_no
      - courseName     → courses.name
      - studentName    → students.full_name
      - issuedDate     → TODAY formatted as "DD MMM YYYY" or "YYYY-MM-DD"

   b. Calculate pixel position:
      pixel_x = (tag.x / 100) * width_px
      pixel_y = (tag.y / 100) * height_px

   c. Apply text style:
      - font-size: tag.properties.fontSize (px)
      - font-family: tag.properties.fontFamily
      - font-weight: map fontWeight → numeric
          normal   → 400
          medium   → 500
          semibold → 600
          bold     → 700
      - color: tag.properties.fontColor (hex)
      - opacity: tag.properties.opacity / 100

   d. Render text at (pixel_x, pixel_y) centered horizontally on that point
      (i.e. text anchor = center)

4. If signatureLayout and signatureFileUrl exist:

   a. Load signatureFileUrl → decode image (PNG recommended for transparency)

   b. Calculate signature dimensions:
      sig_width_px  = (signatureLayout.width / 100) * width_px
      sig_height_px = sig_width_px * (signature_image_height / signature_image_width)  # maintain aspect ratio

   c. Calculate pixel position (center anchor):
      sig_x = (signatureLayout.x / 100) * width_px  - (sig_width_px / 2)
      sig_y = (signatureLayout.y / 100) * height_px - (sig_height_px / 2)

   d. Apply rotation:
      Rotate the signature image by signatureLayout.rotation degrees around its center

   e. Apply opacity:
      alpha = signatureLayout.opacity / 100

   f. Composite the signature image onto the certificate at (sig_x, sig_y)

5. Convert composed image to PDF
6. Upload to storage → save URL in issued_certificates.generated_pdf_url
```

### Text Rendering Notes

- **Anchor point:** The `x`, `y` coordinates represent the **center** of the text, not the top-left corner
- **Text baseline:** Vertically, `y` should be the **baseline** of the text
- **Font fallback:** If a decorative font (e.g. `Brush Script MT, cursive`) is not available on the server, fall back to `cursive` → then `serif`
- **Opacity:** Applied to the entire text element, not the background
- **Line wrapping:** Text should NOT wrap — truncate or scale down if too long

### Signature Rendering Notes

- **Anchor point:** The `x`, `y` coordinates represent the **center** of the signature image
- **Aspect ratio:** Always maintain the original aspect ratio of the uploaded signature image. The `width` field controls the width; height is derived proportionally
- **Rotation:** Rotate around the center of the image. Value is in degrees (positive = clockwise)
- **Opacity:** Applied to the entire signature image as alpha compositing
- **Transparency:** PNG images with transparent backgrounds are recommended for best results
- **Render order:** The signature should be rendered **after** all text tags (i.e. on top of tags)
- **Optional:** If `signatureFileUrl` is `NULL` or `signatureLayout` is `NULL`, skip signature rendering entirely

### Recommended Libraries

| Language | Library |
|----------|---------|
| Node.js | `sharp` + `@napi-rs/canvas`, or `puppeteer` (HTML → PDF) |
| Python | `Pillow` + `reportlab`, or `WeasyPrint` |
| Java | `Apache PDFBox` or `iText` |
| PHP | `imagick` + `fpdf` |

> **Simplest approach:** Render the template image + tags + signature as HTML/CSS and use `puppeteer` / headless Chrome to print to PDF. The `x`/`y` values work directly as CSS `position: absolute; left: X%; top: Y%; transform: translate(-50%, -50%)`. For signatures: `position: absolute; left: X%; top: Y%; width: W%; transform: translate(-50%, -50%) rotate(Rdeg); opacity: O`.

## Notes for the Backend Developer

1. **`tagLayout` is the single source of truth** — store the full JSON from the frontend as-is in the JSONB column. Do not split it into relational rows.

2. **`sampleValue` is frontend-only** — the editor uses it for live preview. Never store or expect it in API payloads.

3. **Position unit is percentage (0–100)**, not pixels. This keeps the layout resolution-independent. Multiply by `image_width_px / 100` and `image_height_px / 100` at render time.

4. **On certificate issuance**, the rendered text anchor should be `center-horizontal` at the given `x%` position. This mirrors the CSS `transform: translateX(-50%)` the frontend uses.

5. **File upload** should accept only image formats (no PDF templates — PDF is only accepted as a preview read-only format that can't have tags placed on it in the editor).

6. **Verification number format** suggestion: `CERT-{YYYY}-{5-digit-padded-sequence}` e.g. `CERT-2026-00042`. Make it unique and indexed.

7. **Increment `issued_number`** on the template atomically when issuing to avoid race conditions.

8. **Digital signature is optional.** The frontend sends `signatureFile` + `signatureLayout` only if the admin toggled the signature on and uploaded an image. If absent, the columns remain `NULL`. When editing a template, the signature can be added, replaced, or removed independently via the dedicated `/signature` and `/signature-layout` endpoints.

9. **Signature image storage:** Store signature images in a separate directory from template images (e.g. `certificates/signatures/`). Suggested naming: `{template_id}-signature.{ext}`.
